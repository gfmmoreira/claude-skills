# skill-evolver

Claude makes mistakes. You correct it. Usually you just move on.

Over time those corrections pile up and nothing changes, because Claude doesn't remember them across sessions. skill-evolver closes that loop.

It goes back through your past Claude Code sessions, finds the moments where you pushed back or corrected Claude, spots the patterns, and proposes rule changes — with the actual quotes from your sessions as evidence. You decide what to apply. Nothing changes automatically.

The loop: frustration → evidence → proposed fix → you decide.

## What to expect

Run `/skill-evolver`. It scans the last 30 days of sessions. If it finds the same failure happening at least twice across different conversations, it proposes a fix. A typical output looks like:

> Claude invented Salesforce field names in 4 sessions across 3 conversations.
> Proposed rule: never state a field name as fact without verifying it first.
> Here's the exact line to add to your config.

It catches three types of failure:
- Claude stated something as fact without checking (invented field names, wrong permissions, made-up test results)
- Claude jumped straight to searching or coding when you asked for an explanation first
- Claude ignored a constraint you explicitly stated (wrong date range, wrong repo, wrong language)

Run it again after 30 days and it tells you whether the fixes held.

## Usage

```
/skill-evolver
/skill-evolver 90    # look back 90 days instead of the default 30
```

## Requirements

- Claude Code (desktop or CLI) with `/insights` available
- `jq` — install with `brew install jq`
- `zsh` — standard on macOS

The scanner depends on session analysis files that `/insights` generates. If those files are missing or stale, the skill will prompt you to run `/insights` first.

## Output

Everything lands in `~/.claude/evolver/`:
- `proposals/` — one file per proposed fix, with evidence and the exact text to add
- `reports/` — summary per run
- `raw/` — raw evidence for debugging

Proposed fixes target `~/.claude/CLAUDE.md`. If your Claude rules live somewhere else, update `SKILL.md` to point there.

## Caveats

The scanner reads `~/.claude/usage-data/facets/*.json`, generated by `/insights`. If Anthropic changes that file format, the scanner will break silently — worth checking `scan.sh` if you get zero results after a Claude Code update.

The fallback regex in `scan.sh` has two layers. `NEGATIVE_RE` is sourced from [alex000kim/claude-code](https://github.com/alex000kim/claude-code/blob/6aa7e7f8789014d42247a0545ab4e9d4e531b0f2/src/utils/userPromptKeywords.ts#L8) — it's the same pattern Claude Code itself uses to detect user frustration signals (wtf, this sucks, horrible, etc.). `FRUSTRATION_RE` is personal vocabulary tuned to your own correction phrases ("that's a lie", "cut that crap"). Edit both in `scan.sh` to match how you actually express frustration.
